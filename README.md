# Dynamic Voices (ฉบับภาษาไทย)

บอท Discord สำหรับสร้างและจัดการห้องเสียงแบบไดนามิก สมาชิกสามารถเข้าห้องต้นทางเพื่อให้บอทสร้างห้องเสียงส่วนตัวหรือสาธารณะให้โดยอัตโนมัติ พร้อมห้องข้อความและ Role สำหรับควบคุมสิทธิ์การเข้าถึง

> ชื่อโปรเจกต์: `dynamic-voices`  
> เวอร์ชันใน package.json: `0.2.0`  
> ภาษาโปรแกรม: TypeScript  
> ไลบรารี Discord: discord.js `14.14.1`

## ความสามารถที่มีใน Source Code

- สร้างห้องเสียงสาธารณะเมื่อสมาชิกเข้าห้องต้นทางที่กำหนด
- สร้างห้องเสียงส่วนตัวเมื่อสมาชิกเข้าห้องต้นทางส่วนตัวที่กำหนด
- สร้างห้องข้อความและ Role สำหรับห้องไดนามิกแต่ละห้อง
- ย้ายสมาชิกไปยังห้องเสียงที่สร้างขึ้นโดยอัตโนมัติ
- ลบห้องเสียงและ Role เมื่อไม่มีสมาชิกเหลืออยู่
- เชิญสมาชิกเข้าห้อง, เตะสมาชิก และโอนสิทธิ์เจ้าของห้อง
- เปลี่ยนชื่อห้อง และสลับการมองเห็นระหว่างสาธารณะกับส่วนตัว
- เปิด/ปิดสิทธิ์ให้สมาชิกทุกคนในห้องเชิญคนอื่นได้
- เลือกเก็บห้องข้อความเป็นห้องเก็บถาวรเมื่อห้องเสียงปิด

## คำสั่ง Slash

### `/voice`

ใช้จัดการห้องไดนามิกที่ผู้ใช้เป็นเจ้าของ หรือห้องที่ผู้ใช้อยู่ในขณะนั้น

| คำสั่งย่อย | การทำงาน |
|---|---|
| `/voice invite user` | เชิญสมาชิกเข้าห้อง |
| `/voice kick user` | นำสมาชิกออกจากห้อง |
| `/voice transfer user` | โอนความเป็นเจ้าของห้องให้สมาชิกคนอื่น |
| `/voice rename name` | เปลี่ยนชื่อห้อง |
| `/voice togglevisibility` | สลับห้องสาธารณะ/ส่วนตัว |
| `/voice inviteall` | อนุญาตหรือยกเลิกการอนุญาตให้สมาชิกในห้องเชิญคนอื่น |
| `/voice archive` | เปิด/ปิดการเก็บห้องข้อความเป็นคลังเมื่อห้องเสียงปิด |
| `/voice info` | ดูข้อมูลห้องปัจจุบัน |
| `/voice close` | ปิดและลบห้อง |

### `/settings`

ใช้ตั้งค่าบอทในเซิร์ฟเวอร์ ต้องมีสิทธิ์จัดการเซิร์ฟเวอร์

| คำสั่งย่อย | การทำงาน |
|---|---|
| `/settings view` | ดูค่าตั้งค่าทั้งหมด (ใน Source Code ปัจจุบันยังตอบ `NIY` จึงยังไม่ทำงาน) |
| `/settings get key` | ดูค่าของการตั้งค่าที่ระบุ |
| `/settings set key value` | กำหนดค่าการตั้งค่า |

คีย์ที่รองรับ:
- `NEW_PUBLIC_VOICECHANNEL` — ID ของห้องเสียงต้นทางสำหรับสร้างห้องสาธารณะ
- `NEW_PRIVATE_VOICECHANNEL` — ID ของห้องเสียงต้นทางสำหรับสร้างห้องส่วนตัว

## ความต้องการของระบบ

- Node.js 20
- npm
- บอท Discord และ Token
- ฐานข้อมูล MySQL สำหรับโหมด Production
- SQLite สำหรับโหมด Development/Test ตามการตั้งค่าใน Source Code

## ติดตั้ง Dependencies และ Build

```bash
npm install
npm run build
```

เมื่อ Build สำเร็จ TypeScript จะสร้างไฟล์ JavaScript ไว้ในโฟลเดอร์ `dist/`

## ตั้งค่า Environment

คัดลอกไฟล์ตัวอย่างเป็น `.env`:

```bash
cp .env.preset .env
```

กำหนดค่าต่อไปนี้ใน `.env`:

```env
DD_DISCORD_BOT_TOKEN=ใส่โทเคนบอท

DD_DBPROD_NAME=ชื่อฐานข้อมูล
DD_DBPROD_USER=ชื่อผู้ใช้ฐานข้อมูล
DD_DBPROD_PASS=รหัสผ่านฐานข้อมูล
```

**หมายเหตุ:** โค้ดเชื่อมต่อ MySQL ใน `src/database/dbmanager.ts` ปัจจุบันส่งค่า user/password/database ไว้ใน `dialectOptions` และไม่ได้ระบุ host อย่างชัดเจน ควรแก้การตั้งค่า Sequelize ก่อนใช้งาน Production จริง โดยกำหนด `host`, `database`, `username` และ `password` เป็นตัวเลือกหลักของ Sequelize ให้ถูกต้องตามเซิร์ฟเวอร์ฐานข้อมูล

## เริ่มต้นใช้งาน

โหมด Development:

```bash
npm run dev
```

โหมด Production หลัง Build:

```bash
npm start
```

`npm start` เรียก `node .` และ package.json กำหนด `main` เป็น `dist/bot.js`

## ตั้งค่าห้องต้นทางใน Discord

1. สร้างห้องเสียงต้นทางสำหรับห้องสาธารณะ
2. สร้างห้องเสียงต้นทางสำหรับห้องส่วนตัว
3. คัดลอก ID ของห้องเสียงทั้งสองห้อง (เปิด Developer Mode ใน Discord ก่อน)
4. ใช้ `/settings set` เพื่อกำหนดค่า `NEW_PUBLIC_VOICECHANNEL` และ `NEW_PRIVATE_VOICECHANNEL` ให้เป็น ID ของห้องที่ตรงกัน
5. ตรวจสอบสิทธิ์บอทให้สามารถจัดการช่องเสียง/ข้อความ, จัดการ Role, ดูช่อง และย้ายสมาชิกได้

## สิ่งที่ควรตรวจสอบก่อนเปิดใช้งานจริง

- เปิด Privileged Gateway Intent `SERVER MEMBERS INTENT` ใน Discord Developer Portal เพราะบอทใช้ `GuildMembers`
- กำหนด Permission ของบอทให้เหมาะสม และวาง Role ของบอทให้อยู่สูงกว่า Role ที่บอทต้องจัดการ
- ตรวจสอบการตั้งค่า MySQL ใน `src/database/dbmanager.ts` ก่อน Production
- สร้างโฟลเดอร์ `logs` หากระบบโฮสต์ไม่ได้สร้างให้โดยอัตโนมัติ
- ตรวจสอบว่าแพลตฟอร์ม Cloud เก็บข้อมูลถาวรได้ หรือใช้ MySQL ภายนอก เพราะ SQLite ในพื้นที่ชั่วคราวอาจหายเมื่อรีสตาร์ต/Deploy ใหม่
- ทดสอบการสร้างห้อง การย้ายสมาชิก การลบห้อง และการจัดการสิทธิ์ในเซิร์ฟเวอร์ทดสอบก่อน
